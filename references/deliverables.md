# 交付物：一次制作，多种成片

代码驱动的片子最大的优势是**可以按画幅重新排版，而不是裁切**。在动手前就把交付清单写进 `plan.json.deliverables`，镜头和画面规范按清单设计。

## 1. 交付清单（先定，再做）

```json
"deliverables": [
  {"id": "hero",     "aspect": "16:9", "duration": 48, "sound": "on",  "use": "B站 / YouTube / 发布会"},
  {"id": "vertical", "aspect": "9:16", "duration": 30, "sound": "off", "use": "视频号 / 小红书 / Reels", "from": "hero"},
  {"id": "cut15",    "aspect": "16:9", "duration": 15, "sound": "off", "use": "信息流贴片", "from": "hero"},
  {"id": "loop",     "aspect": "16:9", "duration": 8,  "sound": "none", "loop": true, "use": "官网 hero"}
]
```

规则：

- 至少一个主片（hero）。其他版本写 `from` 说明从哪支派生。
- `sound: off` 的版本必须通过静音测试（见 [策略](strategy.md)）。
- 15 秒版只保留 hook + aha + 品牌/CTA；6 秒版只有一个画面一句话。不要把 48 秒片子加速压成 15 秒。
- 带 `shots` 列表的派生版本在渲染时背靠背重排；用 `scripts/derive_plan.py plan.json --deliverable <id>` 生成它的时间表，单独配乐（`score.py`）和混音（`mix_audio.py --name <id>`）。
- 竖版要按手机尺寸重建产品窗口（例：560 宽的窄窗口，让产品自己切到窄布局），不要把桌面窗口缩小塞进去——那样正文只剩手机上的 7pt。
- 常见组合：发布主片 16:9 + 竖版 9:16 + 15 秒剪版 + 每个功能一条单条短片 + 官网静音循环。

## 2. 竖版不是裁切

- 重新排版：标题放上部，产品界面放中部并放大（竖屏宽度只有 1080px，界面倍数要重新算，正文仍 ≥ 22px 等效）。
- 横向的并排布局改为上下堆叠；横向平移改为纵向推拉。
- 安全区：顶部约 10%、底部约 20%、右侧约 12% 会被平台 UI（标题、按钮、评论）遮挡，关键文字和主角避开。
- 字号整体放大；每屏字数减少。

## 3. 平台规格速查（发布前再核对平台最新规则）

| 平台 | 主画幅 | 分辨率 | 封面 | 备注 |
|---|---|---|---|---|
| B站 | 16:9 | 1920×1080 | 16:9；缩到约 1/4 仍要读得出标题 | 横屏为主；可加章节 |
| YouTube | 16:9 / Shorts 9:16 | 1920×1080 / 1080×1920 | 16:9，避开右下时长角标 | |
| 小红书 | 3:4 或 9:16 | 1080×1440 / 1080×1920 | 3:4（瀑布流占位最大） | |
| 微信视频号 | 9:16 或 横屏 | 1080×1920 | 竖版原图，多场景复用 | |
| 抖音 | 9:16 | 1080×1920 | 竖版 | |
| X / LinkedIn | 16:9 或 1:1 | 1920×1080 / 1080×1080 | 首帧即封面 | 默认静音自动播放 |
| 官网 hero | 16:9 静音循环 | 1920×1080，控制码率 | — | 首尾无缝 |

## 4. 无缝循环

- 设计时让最后一个状态回到第一个状态（或让循环点落在一个稳定构图上）。
- 首帧与末帧要几乎相同：`review_sheets.py --loop` 会比较首尾帧差异并报告。
- 循环片不放 Logo 落版和 CTA（放在页面上），不需要开场 hook 的黑场淡入。

## 5. 封面

| 比例 | 设计尺寸（导出 2×） | 用途 | 布局 |
|---|---|---|---|
| 3:4 | 1080×1440 | 小红书、竖向信息流 | 标题上、主图中、标签署名下 |
| 4:3 | 1440×1080 | X、公众号配图 | 左 40% 标题标签，右主图 |
| 16:9 | 1920×1080 | B 站、YouTube 缩略图 | 主图主导，标题更大更少；避开右下时长角标 |

- 只用本片真实渲染的画面（snapshot 出 PNG 比从 MP4 抽帧清晰）；主图缩小后仍认得出；大面积纯黑纯白帧不作辅图。
- 中文主标题 ≤ 约 12 字，可配一行英文；标签 ≤ 4 个。和竞品比较只在用户自己写了时才上封面。
- 三种比例共用元素但**重新排版**，不等比缩放。`review_sheets.py` 的缩略图测试把候选帧缩到 320px 宽，检查是否还读得出。
- 不做伪装成平台界面的封面（假播放量、假按钮）。
- 封面写在 `cover/cover.html`（每个比例一个 `[data-cover]` 元素），`node tools/cover.mjs` 按 2× 导出并核对尺寸。

## 6. 交付包

```
renders/
  hero-16x9.mp4
  vertical-9x16.mp4
  cut15-16x9.mp4
  loop-16x9.mp4        # 无音轨
  clips/<feature>.mp4  # 单条
covers/cover-3x4.png cover-16x9.png
evidence/              # 证据、审片图、评分卡
```

每个文件在交付说明里写明：画幅、时长、有无声音、用途、对应哪个 deliverable id。
