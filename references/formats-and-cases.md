# 片型与案例：学"为什么有效"，不学"长什么样"

先按 `goal`、渠道和素材选片型，再在片型内部从产品推导手法。每个片型写明它适合什么、不适合什么。案例描述来自公开报道和分析文章，**做片前自己看原片**；不要照搬它们的颜色、字体或构图。

## 七种片型

### 1. 无旁白产品片（Linear 式）

- **做法**：没有旁白、没有库存素材、没有抽象 3D。镜头在真实产品里移动，一次只做一个动作；二十秒左右看懂一个功能。
- **为什么有效**：产品本身就是证据；克制让每一次状态变化都被看见。
- **适合**：界面精致、功能可以一眼看懂的工具；开发者、设计师受众；官网 hero、推文。
- **不适合**：价值要靠解释才懂的产品（数据安全、后端能力）。
- **本 skill 的落点**：真组件 + 推近接续 + 聚焦压暗；字幕极少；音效承担反馈。

### 2. 单一主张演示（Apple 式）

- **做法**：一支片只证明一件事，用夸张而真实的演示把它做到极致（例如跌落、泼水、刷脸），情绪优先于参数。
- **为什么有效**：观众只记得住一件事；演示比宣称可信。
- **适合**：有一个明确"杀手功能"的发布；15–30 秒贴片。
- **本 skill 的落点**：`singleMessage` + `ahaMoment` 撑满全片；其余功能一律不出现。

### 3. 痛点 → 反差 → 解决（经典 explainer，Slack / Dropbox 类）

- **做法**：先让观众在痛点里认出自己，再展示差距，最后产品解决并给证据。
- **为什么有效**：模拟真实购买决策——先看到"现在"和"可能"的差距。
- **适合**：新产品首发、面向还没用过的人、落地页。
- **注意**：痛点必须真实可辨认，不要演成夸张小品；解决部分回到真组件。

### 4. 连续运镜穿越（Raycast / Figma 类）

- **做法**：一个不断镜的连续平移/推拉，把视线从输入处带到结果处；片尾摄像机拉远，界面缩成一个点变成 Logo。
- **适合**：流程型功能（输入 → 执行 → 结果）、空间感强的界面。
- **注意**：落点要实测；整片只用一个连续镜头时，要有节奏变化（停顿、加速）。

### 5. 创始人/团队变更日志（Arc 式）

- **做法**：CEO 或产品负责人对着镜头讲这个月更新了什么、为什么这么做，承认犹豫和取舍，穿插产品画面，像一集连载节目。
- **为什么有效**：真诚与幕后理由建立关系；老用户会追着看。
- **适合**：已有社区的产品、每月更新。
- **本 skill 的落点**：人物素材由用户提供（本 skill 不生成真人）；产品插入镜头用真组件；旁白转字幕要点。

### 6. 小功能快切（倒数清单）

- **做法**：每个小更新 2–4 秒：一个词、一个动作、一个结果，节奏卡拍，配计数。
- **适合**：版本里有很多独立的小改进。
- **注意**：每条仍要有对象 + 结果，不能只剩关键词。

### 7. 功能单条系列（changelog clips）

- **做法**：每个功能一条 10–20 秒短片，展示"点击 → 中间状态 → 结果"，跟文字 changelog 一起发（Stripe、Linear、Resend 类的周更 changelog 常配短视频或动图）。
- **适合**：持续发布、推文、帮助中心、邮件。
- **本 skill 的落点**：同一套组件和画面规范批量出片；每条可以静音循环。

## 跨案例的共同做法（多个分析文章一致观察到的）

| 做法 | 说明 | 在本 skill 里 |
|---|---|---|
| 压暗非重点界面 | 被分析的 SaaS 发布片几乎都会模糊或去色压暗周边 UI，把注意力逼到新功能上 | 视觉词汇"聚焦压暗"；属于取景，不是重画界面 |
| 推近到单个控件 | 大多数片子会把镜头推到一个按钮或菜单上 | "放大取景 + 推拉" |
| 压缩时间 | 跳过加载、加速复杂操作；光标路径干脆利落 | "时间压缩"；必须保留"中间状态"让人看懂因果 |
| 点击有反馈 | 局部涟漪或整屏状态变化，给点击一个"回应" | "交互强调"；配 click 音效 |
| 抽象化看不见的过程 | 后台处理、编译等用几何图形表达 | 只用于真实存在的过程；不代替可展示的界面 |
| 拉远收束到 Logo | 片尾把界面拉远，变成品牌标识 | "拉远落版" |
| 不从功能清单开场 | 好片都在制造一个认知转变，而不是罗列 | `singleMessage` |

上述比例和观察来自小样本分析（例如 advids 对 7 支 SaaS 发布片的拆解），当作经验而非定律。

## 2026-09 代码渲染视频案例（Opus 5.5 发布周）

这一周社区里大量"全部用代码渲染"的产品片、讲解片，完整案例和提示词整理在 [joeseesun/opus-video-prompts](https://github.com/joeseesun/opus-video-prompts)。对本 skill 有用的是它们**为什么有效**：

| 案例 | 有效的原因 | 在本 skill 里 |
|---|---|---|
| 一句话"modern slick and punchy"发布片（Deedy） | 抽象技术产品用几何和字卡讲清一个概念，几秒看懂 | 片型 2/3；quick 档快速通道；但产品片仍要真实界面 |
| UI 形态变换循环（zero） | 一个元素不断变成下一个 UI，光标驱动，120 BPM 每拍一变，首尾同帧 | 片型 7 的循环版；[弹簧与形变](visual-vocabulary.md#弹簧与形变) |
| 高端极简产品片模板（zero） | 一镜一念、大留白、一个强调色、禁用清单、切点实测落拍、子帧动态模糊、先给分镜再写代码 | DIRECTION 禁用清单、`beat_grid.py`、`render.mjs --blur` |
| Remotion App 宣传片（Danny Stuart） | 先分镜再编码；描述质量时给参考视频而不是形容词；用镜头语言（dramatic cuts、orbiting camera） | 三个确认点；拆参考 |
| 30 秒企业讲解五幕（Alex Prompter） | 问题 → 我做什么 → 三步怎么用 → 一个证据 → 名字，结构写死 | 片型 3 的最短骨架 |
| 鸡尾酒配方图解（Rory Flynn） | 一个清晰的系统：步骤计数、用量、进度条，一步一个状态 | 小功能快切、功能单条系列的信息设计 |

共同的教训：结构（时长、场景数、每场景讲什么）比形容词重要；禁用清单比"要高级"有效；"一次成型"往往是两轮以上。

## 审美参照：Linear / Vercel / Raycast 风格的真正内核

常被模仿的不是渐变，而是：精确的字体系统和清晰的字号阶梯、近灰阶底色 + **一个**克制的强调色、大量留白、每段只讲一件事、动效只用来引导注意。只抄渐变不抄克制，会"像穿了别人的戏服"。如果产品本身不是这个气质，不要硬套。

## 选型速查

| goal | 首选片型 | 常见长度 | 主画幅 |
|---|---|---|---|
| 新产品首发认知 | 3 或 2 | 30–60s | 16:9 + 9:16 |
| 大版本发布 | 1 或 4，辅以 6 | 45–60s | 16:9 |
| 老用户采用新功能 | 7 或 1 | 10–20s/条 | 16:9 / 1:1 静音循环 |
| 月度更新 | 5 或 6 | 60–120s | 16:9 |
| 投放转化 | 2 或 3 | 15–30s | 9:16 / 4:5 |
