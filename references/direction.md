# 影片方向：写代码之前的设计

前置：[广告策略](strategy.md) 的五个字段（goal / audience / singleMessage / ahaMoment / cta）已经写好，片型已按 [片型与案例](formats-and-cases.md) 选定。方向服务于策略，不反过来。

片子好不好看，主要由写代码前的决定决定：讲什么、什么气质、每个镜头的主角是谁、字多大、界面放大几倍。这些写进 `DIRECTION.md`，然后才搭镜头。

> 为什么要这一步：模型会优先满足能量化的东西。只按"动作落拍率、切点在小节线上"迭代，能得到指标满分但画面拥挤、字小、像幻灯片的片子。把规范写成数字、把镜头写到每一秒，质量才落得下来。

## 1. 拆参考（有参考视频时）

```bash
ffmpeg -i ref.mp4 -vf "fps=1,scale=400:-1,tile=6x8" -frames:v 1 ref-sheet.png
```

逐个列手法：是什么 / 表达什么（速度？秩序？连接？）/ 出现在哪段 / 持续多久。**学做法，不抄样子**：参考片的颜色、图形、字体属于它的品牌，写清本片采用与否、改写成什么、依据是什么。

## 2. 产品气质（从仓库和用户输入回答，不凭印象）

- 谁在用、什么情境、用起来什么感觉（冷静专业 / 轻快 / 温暖 / 硬核 / 安静）。
- 设计语言：色板、字体、圆角、阴影、明暗主题、图标风格，写到文件路径。
- 母题候选（能直接变成画面的产品元素）：标志的几何构造、核心界面本身、产品处理的数据形态、领域隐喻（写作→纸与墨，设计→构造线，音乐→波形，财务→走势线）、产品名的字面意象。

## 3. 三个方向，沿不同的轴拉开

每个方向在每个轴上选一项；三个方向两两之间**至少三个轴不同**，且各自内部自洽。

| 轴 | 取向举例 |
|---|---|
| 底色与光 | 黑舞台+发光 / 纸白+墨线 / 品牌色大色块 / 明暗交替 |
| 字体声音 | 超细大字 / 粗重冲击 / 衬线编辑感 / 等宽技术感 / 圆润亲和 |
| 母题来源 | 标志几何 / 界面本身 / 数据形态 / 领域隐喻 / 用户场景 |
| 镜头语言 | 平面编辑排版 / 3D 舞台 / 微距特写 / 一镜到底 / 录屏质感 |
| 转场 | 硬切卡拍 / 穿越缩放 / 遮罩擦除 / 形状变形 / 匹配剪辑 |
| 节奏 | 发布会从容 / 预告片紧凑 / 轻快俏皮 / 安静叙事 |
| 声音 | 电子脉冲 / 钢琴弦乐 / 打击乐 / 氛围铺底 / 用户曲子 |

另加一个**破格方向**：刻意违反这个品类的惯例（见 [原则](principles.md)），至少做 1–2 张真实静帧。

按气质、受众、发布平台选一个，写理由：必须说明它怎样服务 `singleMessage` 和 `goal`。

## 4. 本片专属手法（3–5 条）

每条写成"**因为产品有 X，所以用 Y**"。写不出 X 就删掉。其中一条标为**签名时刻**：只属于这个产品、观众会截图转发的那一秒。推导方式举例（不是菜单）：

| 产品有 | 可以长成 |
|---|---|
| 点阵/网格构成的标志 | 粒子从远处落进点阵的每一格 |
| 接了很多服务/插件（数量有出处） | 成员沿倾斜的环绕着核心界面转 |
| 面向开发者 | 用产品自己的源码组成的字符场 |
| 写作/笔记 | 逐笔写出、纸纹、墨迹晕开 |
| 数据分析 | 真实图表路径逐段画出，数字滚动落定 |
| 协作 | 多个光标同时进入，状态实时合并 |
| 用户在多个工具间来回切换（痛点） | 槽位轮换开场：今天 A、明天 B，间隔越来越快 |

更多手法与实现要点见 [视觉手法词汇](visual-vocabulary.md)。

## 5. 反重复

- **跨片**：动手前看同一工作区里之前的 `DIRECTION.md` 和 `evidence/review/contact-*.png`，列出它们的开场、章节处理、背景、配乐。新片至少三个轴不同，不原样复用开场、章节和背景手法。
- **片内**：主角、辅助信息、背景各有出场方式；相邻镜头换取景（全景↔特写↔大字）或换明暗；同一转场不连用三次以上。

## 6. 叙事结构（按内容选）

- 主张 → 证明 ×3–5 → 小功能快切 → 收尾（最常见，不是默认答案）
- 问题 → 转折 → 解决（明确痛点的更新）
- 完整做完一件真实任务（Agent、工作流产品）
- 一镜到底穿过产品各区域（空间感强的界面）
- 前后对比（性能、改版）· 倒数清单（很多小更新）· 一天的使用（日常工具）

## 7. 画面规范（写成数字）

- 画幅、帧率、底色、安全区（重要内容避开底部约 13%，竖版再避开右侧互动栏）。
- 字号阶梯：主标题 / 次标题 / 说明，中英文各自字号、字重、字体来源。
- 界面上镜倍数 ≈ 22 ÷ 产品正文像素（使 1080p 下正文 ≥ 22px）。完整窗口只作建立镜头。
- 明暗：产品有暗色主题且片子走暗调，直接用它的暗色主题。
- 动效语法：入场方式、缓动族（界面状态变化优先用弹簧，见 [视觉手法词汇](visual-vocabulary.md#弹簧与形变)）、时长范围。
- **禁用清单（必写）**：列出本片不用的手法。模板感大多来自这些默认效果，写下来比"要高级"有效。起点清单（按片子删改，破格要写理由）：冲击波圆环、粒子爆炸、RGB 分离、镜头抖动、镜头光晕、霓虹辉光、网格地面、闪烁背景、回弹缓动、UI 外框上的渐变、图标描边粗细不一、无意义的空等。

## 8. 镜头表

每个镜头一行：时间 / 唯一主角 / 画面与动作（带子拍时间）/ 上屏文案 / 声音。每个镜头至少一次状态变化或镜头运动；完全静止超过 2.5 秒只能是在给观众读字。镜头有长有短：开场与快切短，功能证明长。

镜头表的 id 与 `plan.json.shots[].id` 一一对应。在表里标出四个角色（同时写进 `plan.json.shots[].role`）：

- `hook`：首个镜头，首帧就有内容，3 秒内抓住（见 [策略](strategy.md#3-开场-3-秒hook)）
- `aha`：证明 `singleMessage` 的那个画面，停留足够让人看清因果
- `brand`：产品首次可被认出的镜头，应在 5 秒内
- `cta`：结尾给出下一步

一个镜头可以同时担多个角色（例如开场直接是产品界面：hook + brand）。

多画幅交付时（见 [交付物](deliverables.md)），镜头表为每个画幅注明构图差异；竖版单独写一版取景。
