# 声音：来源、编曲、对位、让位

## 音乐来源（按顺序）

1. **用户提供的曲子**或有授权的曲库：直接用，先**实测**节拍再排镜头：

   ```bash
   python3 <skill-dir>/scripts/beat_grid.py assets/song.mp3 --plan plan.json --write
   ```

   写入 `audio.beatGrid: {bpm, offset(首个强拍), measured: true}` 和 `audio.drop`（能量抬升最大的小节），并列出每个镜头起点离最近强拍差几帧。规则：**切点落强拍，界面动作落拍**，`drop` 留给 aha 或品牌镜头。这是测量不是真值：配一条 click 音轨听一遍再锁；半速/倍速测错时用 `--bpm-range 110-140` 纠正。
2. **本机确实可用的生成模型**：权重在本地、运行环境装好才算可用，只有配置缓存不算。生成后照样按分镜检查段落。
3. **代码原创合成**（默认）：`scripts/score.py plan.json --mood warm|bright|tech|ambient|punchy --key D` 从镜头表推出编排（强度随镜头变化、品牌镜头落重拍、最后一镜 IV–V–I 收束），固定种子可复现；听完不满意就改脚本里的编排段，或为这支片子另写合成脚本。

不要下载来路不明的 BGM，不扒参考视频的音乐，不把示例曲改名当新配乐。

## 旁白（可选）

默认无旁白（片型 1、2、6、7）。片型 3、5 或用户要求时加旁白：

- 来源：用户录音 > 用户授权的声音克隆 > 本机可用的 TTS 或用户提供的 TTS 接口（豆包、千问、海螺、Kokoro 等）。不克隆未授权的真人声音。混音时写进 `plan.audio.voice`，`mix_audio.py` 会给人声让位。
- 接第三方 TTS 时：接口文档放进工程（如 `TTS.md`），key 放 `.env`，并建议用户在 `.claude/settings.json` 加 `"deny": ["Read(./.env)"]`，由脚本读取 key，模型不读；接口有水印参数就关掉并记录。
- 先写旁白稿再定镜头时长：中文约 4–5 字/秒；画面动作落在旁白提到它的那一刻。
- 旁白说出产品名和 CTA（ABCD：用声音强化品牌与指引）。
- 旁白要点同步做成 supers，静音也成立。
- 有旁白时配乐整体压低，旁白段落给人声留出中频空间。

## 编曲从镜头表来

逐段写音乐要做什么，时间直接取 `plan.json` 的镜头边界：开场是渐强、悬念还是直接进节奏？品牌、章节、落版要不要冲击点、冲击前留不留一瞬空白？读字和看操作的段落让出空间（乐器变少、旋律退后）；快切段落加密节奏或上升音；结尾完整和声收束并留尾音。

## 音色从气质来

| 气质 | 配器与手法 |
|---|---|
| 冷静、高端、技术 | 宽 supersaw 铺底、pluck 琶音、侧链底鼓、次低频冲击 |
| 轻快、友好 | 明亮键盘和弦、短音旋律、轻拍手、马林巴类 |
| 温暖、人文 | 钢琴或拨弦主导、慢速、长混响、少打击乐 |
| 有力、紧凑 | 打击乐主导、低音脉冲、密集上升音、切分 |
| 安静、专注 | 氛围铺底、稀疏铃音、几乎没鼓 |

合成要点：按总线（鼓、低音、铺底、琶音、效果）分别合成再混；所有时间用拍/小节换算，改片长时一起改并检查尾音越界；**画面动作的点击、提示音不写进配乐**，它们是独立音效。导出后看频谱与每秒响度——低频过重是合成配乐最常见的问题。

## 音效来源

1. 用户已有、来源清楚的素材库。
2. 本机已有、许可清楚的录音素材库（读它的许可说明并记进工程）。
3. 素材站（如 Pixabay）：下载链接必须来自真实下载操作，不编造 CDN 地址；拿不到就如实记录，走下一项。
4. 自带合成：`scripts/make_sfx.py --out assets/sfx [--bright 0.85]` 生成 click、click-alt、pop、toggle、typing、ding-dong、success、error、whoosh、riser、impact（峰值统一 −3 dBFS，和录音素材一样好配增益）。

| 画面动作 | 声音 | 选择重点 |
|---|---|---|
| 点击、选中 | 短 UI click | 起音干净、不刺耳 |
| 弹出、出现 | pop、轻 toggle | 轻巧有反馈 |
| 输入 | 键盘短簇 | 与画面打字节奏一致 |
| 通知、完成 | 双音提示、确认 chime | 可辨认，拖尾不长 |
| 结构变化 | whoosh、glitch | 只给真正换段 |
| 冲击、落版 | 低频冲击 | 与配乐冲击点叠加或二选一 |

30–60 秒片一般 4–6 种职责即可。每个核心功能组选一个最有反馈感的状态变化标 `soundRequired: true`。不要每个字出现都"叮"。

## 对位

```bash
python3 <skill-dir>/scripts/sfx_landmarks.py assets/sfx/*.wav
```

- 点击、按键、弹出：用**起音点**对齐动作。whoosh、冲击、上升音：用**峰值**对齐切点（声音要比画面先开始）。
- 关系式：`cue.at + cue.syncOffset = shot.start + action.at`。`check_plan.py` 会核对这条，偏差 > 2 帧报出。
- 增益按实测峰值设：录音素材接近 0 dBFS，合成音效往往低很多，同样 gain 听感差很多。音效出现那一刻的峰值不应低于压低后的配乐。

## 让位（ducking）与混音

`scripts/mix_audio.py plan.json` 按 cue 的 role 给音乐做让位包络（多个重叠取最深，不相乘）、两遍 loudnorm，并在 `evidence/audio-mix.json` 报告每个 cue 的对位帧差和**可闻度余量**（音效峰值 − 让位后音乐峰值；低于 −3 dB 会警告）。派生版本：`derive_plan.py` → `score.py` → `mix_audio.py --name vertical`。试听起点，**不是标准**：

| 声音职责 | 配乐压低 | 起音前 / 保持 / 恢复 |
|---|---|---|
| 点击、切换 | ~3 dB | 40ms / 100–120ms / 200–240ms |
| 输入 | ~2.5 dB | 40ms / 350ms / 250ms |
| 转场 | ~4 dB | 40ms / 160–200ms / 300–350ms |
| 完成、通知 | 5–6 dB | 40ms / 350–450ms / 350–400ms |
| 品牌收尾 | ~5 dB | 40ms / 550ms / 450ms |

多个音效重叠取最深的压低，不层层相乘。音乐不停"抽动"就减少 cue 或延长恢复。

无配音短片最终混音可从 −16 LUFS、true peak ≤ −1.5 dBTP 起步，按平台和听感调整。AAC 编码后重测 true peak。

## 记录来源 `evidence/audio-selection.json`

`music`：来源（用户 / 模型名 / code-original + 脚本路径）、时长、BPM、调性、段落时间。`sfx[]`：作用、来源（库名、作者或详情页）、许可、本地路径；回退时写实际原因。未知就写未知，不编造搜索经历。
