# 产品适配：任何产品都能拿到"真实画面"

底线不变：画面来自真实产品。不同产品，"真实"的来源不同。先按下表选路径，再**录一次真实数据**，之后离线、确定性地渲染。

| 产品类型 | 真实画面来自 | 做法 | 常见难点 |
|---|---|---|---|
| Web / React / Vue 应用 | 业务组件本身 | esbuild 打进视频工程；provider + fixture；`director()` 按时间驱动真实点击和输入 | 路径别名、Tailwind、portal 弹层 → 放进 iframe |
| 插件（Obsidian 等宿主） | 插件真实代码跑在宿主 API 兼容层上 | `assets/adapters/obsidian/`：API shim + 默认主题宿主 + 每镜一个 iframe；VS Code / Chrome 扩展同理写 shim | 宿主外观是重建，要在证据里写明 |
| 只有官网 URL / 已上线 Web | 真实网页状态 | `tools/capture.mjs` 按步骤点击、截取高 DPR 画面和元素坐标；可播放的页面也可以直接放进 iframe 用 `director()` 驱动（录制请求走 `/__proxy`） | 只能展示公开可见的内容；不登录用户账号 |
| 截图 / 设计稿 | 用户提供的真实截图 | 分层裁切 + 摄像机推拉；标注"非运行画面" | 不能伪造截图里没有的状态 |
| CLI / TUI | 真实终端输出 | `scripts/record_terminal.py` 录 asciicast → `kit/terminal.js` 按时间回放，可压缩空等 | 输出太长：只保留关键几行，放大到 ≥ 26px 等宽字 |
| API / SDK / 基础设施 | 真实请求与响应、真实代码、真实耗时 | 用 lab 录制真实请求 → 代码块逐行出现 + 响应按真实延迟流出；看不见的过程用几何表达（见视觉词汇） | 不上屏密钥、真实用户数据 |
| AI / Agent 产品 | 一次真实运行 | 录下事件流（终端或页面）→ `kit/stream.js` 按时间回放；可加速但保留每一步 | 输出不稳定：录一次、固定下来 |
| 移动 App | 模拟器 / Web 构建 | iOS Simulator 录屏或 RN/Flutter Web 渲染进 phone 框；竖版天然合适 | 横版需要设备框和留白 |
| 原生桌面应用 | 录屏或忠实重建 | 经用户同意；重建时尺寸、颜色、字体取自源码，写明"重建" | 不偷偷退化成手绘 |

## 生成式视频素材（Seedance、Runway 等）

社区里有人用视频模型生成人物、场景作为底片，再用代码重绘或叠加。本 skill 的边界：

- **可以**用于不含产品界面的氛围插入（使用场景、情绪镜头），或作为转描（rotoscope）的底片、最终被代码画面完全覆盖。
- **不可以**生成或"补全"产品界面、数据、客户、评价；产品画面仍然只来自上表的真实路径。
- 用到时写进 `evidence/feature-evidence.md`：模型名、提示词、生成日期、许可，交付说明里标注"含生成素材"。只用用户已配置、确实可用的接口和额度，先报预估花费。

## 录制与回放（所有路径通用）

1. `FILM_RECORD=1 node tools/lab.mjs --record --steps lab/flows.mjs`：驱动片中要出现的每一个流程，真实请求经服务端代理写入 `src/fixtures/requests.json`。
2. 渲染时只读 fixture：离线、确定、可复现。缺 fixture 会在 stills / render 报告里列出。
3. 数据是录制当天的真实内容：片中数字（频道数、来源数）以 UI 显示为准，写进 feature-evidence；README 等文档常常过时。
4. 第三方内容（文章、图片）会出现在画面里：尽量选文字为主的条目，少让单张第三方图片占满画面，交付时提醒用户确认。

## 受众也是一种适配

| 受众 | 偏向 |
|---|---|
| 开发者 | 克制、少说多做、真实终端和代码、不夸张 |
| B2B | 证据、效率、前后对比、具体数字（有来源） |
| B2C / 创作者 | 场景、情绪、结果先行、竖版优先 |
