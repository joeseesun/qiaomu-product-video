# 精品评分卡

`review-and-delivery` 用来**找问题**；这张评分卡用来判断**够不够好**。正式交付前填 `evidence/scorecard.md`（`init_project.py` 已生成模板），`check_plan.py --final` 会检查它是否填完、必过项是否全部通过。

## 一、必过项（任何一项不过，不交付）

| # | 测试 | 怎么做 |
|---|---|---|
| G1 | 一句话复述 | 看完一遍，不看文案，能说出 `singleMessage` 吗？（最好找没参与的人） |
| G2 | 3 秒测试 | 只看前 3 秒（`evidence/review/hook-strip.png`），知道这是关于什么的、想继续看吗？ |
| G3 | 品牌识别 | 5 秒内能认出是哪个产品吗？ |
| G4 | 静音测试 | 关掉声音看完，所有主张都能看懂吗？ |
| G5 | 事实 | 每个主张都有来源；没有虚构数字、客户、功能 |
| G6 | 真组件 | 功能镜头是原组件（或经同意的重建/录屏），与 component-usage 一致 |
| G7 | 可读性 | 手机尺寸下（缩到 1/3）中文说明读得清、读得完 |
| G8 | 技术 | 无裂图、裁切、空屏、跳帧、爆音；音画不错位；结尾完整 |
| G9 | CTA | 结尾告诉观众下一步（或按用户要求刻意不放，并记录原因） |

## 二、评分项（1–5 分，精品线：平均 ≥ 4，且无 ≤ 2 的项；共 11 项）

| 维度 | 5 分的样子 | 2 分的样子 |
|---|---|---|
| 单一信息 | 每个镜头都在证明同一句话 | 功能清单平铺 |
| 开场 | 首帧即有内容，3 秒内抓住 | Logo 淡入、黑场、慢热 |
| aha 时刻 | 有一个让人"哦！"的画面，停留够久 | 关键变化一闪而过或被遮挡 |
| 产品推导 | 每个手法说得出产品依据，换个产品就不成立 | 换 Logo 就能给别的产品用 |
| 克制与焦点 | 每屏一个主角，周边被压暗，留白充分 | 满屏元素同时动 |
| 节奏 | 有长有短，动作落拍，停顿有信息 | 均匀的"入场—停—入场" |
| 文案 | 对象 + 动作 + 结果，说人话 | 空泛形容词 |
| 声音 | 配乐服务段落，关键反馈听得见，结尾收束 | 只有 BGM 或音效淹没 |
| 画面质感 | 字号阶梯、对齐、明暗、配色一致 | 字挤、撞图、配色杂 |
| 多版本 | 每个画幅都是重新排版，静音版独立成立 | 竖版是裁切，15 秒是加速 |
| 记忆点 | 有一个签名时刻，看完会想截图转发 | 挑不出一秒能代表这支片子 |

## 三、评审方式

- **盲评优先**：请一个没参与制作的人（或新开一个没有上下文的子代理）只看成片回答 G1–G4，再看评分项。制作者自评容易偏高。
- 每项写一句**证据**（看到的时间点、截图路径），不写"感觉不错"。
- 低于精品线：只改分数最低的两项，改完重评，不要全盘推倒。
- 评分卡是判断工具，不是对外宣传：不要把"自评 4.5 分"写进交付说明当作质量证明，写"评审方式 + 结果"。
